#### T-038 · 操作系统决策（2026-10-02）

> 3. 项目后续可能用到 **Docker / K8s 等云原生技术**，Ubuntu 支持最好。

#### T-038 · 资源决策（2026-10-02，第二轮）

**用途（已定）**：**全栈预演** —— 虚拟机里跑 **Docker + MySQL + Spring Boot jar + Nginx**，模拟 [04-部署方案](04-部署方案.md) §6 的上线架构。

**宿主（已定）**：💻 **笔记本**（i7-7500U / **20 GB 内存**）—— **不是台式机**。理由：

- 台式机物理内存实测仅 **7.4 GB**（07 §3），而全栈预演峰值约 **2.5 GB** → 给完虚拟机就没法再开 IDEA，**开发与预演互相干扰**；
- 笔记本 20 GB 内存，给 6~8 GB 毫无压力，且**两台机器互不干扰、更接近真实上线形态**；
- ⭐ **两个用途的瓶颈正好相反**：**台式机 CPU 强 = 开发机**（07 §8.2 结论**不变**）；**笔记本内存大 = 虚拟机宿主**。

**❌ 已否决：2核8GB（在台式机上）** —— 不是"够不够"的问题，是**物理上给不出来**：8 GB **大于**台式机**全部**物理内存 7.4 GB，VMware 会拒绝开机，或把宿主拖进疯狂换页。另：**CPU 不是瓶颈**（台式机 6 核 12 线程），**内存才是**。

**✅ 采用规格（笔记本）**

| 项 | 值 | 理由 |
|---|---|---|
| vCPU | **2** | 宿主共 2 核 4 线程（07 §8.1）；服务器负载很轻 |
| 内存 | **6 GB**（宽裕可给 **8 GB**） | 全栈峰值 ~2.5 GB；余量留给将来试 K8s<br>⚠️ **2026-10-04 对齐**：这是**当时的计划值**；**实际给的是 8 GB**（见 §3 的 T-038 行、docs/07 §1/§8.5、[README](../README.md)） |
| 磁盘 | **60 GB 精简置备**（thin） | Docker 镜像 + MySQL 数据 + jar；实际占用随用随涨 |
| swap | **4 GB** | 内存不足时的廉价保险 |

**⚠️ 三条纪律**

1. **不要在虚拟机里编译** —— `mvn package` 在台式机做（6 核，快），把 jar 拷到笔记本虚拟机**只运行**；这恰好符合"服务器只运行、不编译"的真实形态；
2. **VMware 不要勾 "Reserve all guest memory"**（预留全部内存），否则宿主内存被立刻锁死；
3. 虚拟机文件放笔记本空间充足的盘，并**精简置备**。
