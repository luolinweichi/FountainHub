## 1. 目标（这个任务要达成什么）

让**社长层可以自己更换首页的背景图**，不用改代码。

### 需求方明确的口径（2026-10-04）

| # | 口径 |
|---|---|
| 1 | **一张固定**背景图（不做"多张轮换"） |

```

### 🎨 2026-10-04 · 接线完成：背景图作用于「整个首页」

**需求方口径（本次实现依据）**：「是整个首页的背景图，**不是 Hero 的**」；一张固定、只作用首页、白色 40% 半透明遮罩。

**做法（以及为什么这么写）**

| 决定 | 理由 |
|---|---|
| 在首页最外层包一层 `.fh-homewrap`（`templates/index.html`），**只有配了图才**加 `fh-on` + 行内 `--fh-home-img:url(...)` | 背景要**整页铺满** —— `.fh-page` 有 `max-width:1200px`，把背景铺在它上面只能盖住中间那一条；而这一层**只在首页存在** → 天然不影响其它页面 |
| 遮罩**不额外加 DOM**，而是与图片叠成**同一个元素的两层 background**：`linear-gradient(rgba(255,255,255,.4), …), var(--fh-home-img)` | ① 少一层 DOM；② **不存在 z-index 层级问题** —— 背景永远在内容之下，白卡片内容天然不受遮罩影响（上一版 `.fh-heromask` 用绝对定位就是栽在这里） |
| `background-size: cover` + `background-attachment: fixed` | 整页铺满且不变形；滚动时背景不动，观感更稳（P1 只验收桌面视口） |
| **删掉** `fh.css` 里两条旧规则（`.fh-heromask`、`.fh-hero[style*=background-image]`） | 它们是上一版"给 Hero 配图"的**死代码**，留着会让下一个人以为 Hero 还能配图 |
| ⚠️ 行内变量用 `\|...\|` 字面量替换 `th:style` | **就是为了不再踩**上一轮那个坑（`th:style` 里拼字符串被当字面量，渲染成 `url(homeBackground)` 而不是真地址） |

**改动文件**：`templates/index.html`（包 `.fh-homewrap`）、`static/css/fh.css`（删 2 条死代码 + 新增 `.fh-homewrap[.fh-on]`）、`templates/admin/settings.html`（预览改整页效果 + 文案）、`controller/HomeController.java`（仅注释）。

**验证结果（真实输出，17 项断言全过）**

```

② 保存背景图：POST /admin/settings/background → 302；设置页出现「首页背景图已更新」        ✅
③ 数据库写入 home_background = 上传后的 URL                                            ✅
④ 游客首页真实渲染出：
   <div class="fh-homewrap fh-on" style="--fh-home-img:url('/uploads/2026/10/b51e….png')">  ✅
⑤ 其它页面 /about /awards /news /me/study：均【不含】整页背景标记（不受影响）               ✅
⑥ 恢复默认：POST …/background/reset → 302；首页标记消失、库里值回到空串                    ✅
⑦ 默认态一致性：把「实时时间戳」与「CSRF token」（每请求都变）归一化后，

**⚠️ 我自己的两个失误（记下来，别再犯）**

1. 验证脚本里用了 `$home` —— 那是 PowerShell 的**只读自动变量**（`$HOME`），赋值**静默失败**，
   结果首页请求根本没发出去，我一度误判成"首页没接线"。**（同类坑：`$a1` vs `$A1` 大小写不敏感。）**
2. 一开始拿**两个不同会话**的首页 HTML 做字节比对 → 必然失败。真因：layout 的 `<head>` 里带着
   **每次请求都变的 CSRF token**，首页还渲染了 `now` 时间戳。**把这两类值归一化之后才是正确的比法。**

### 🐞 2026-10-04 · 接线后**又发现并修掉一个前提 bug**：`/uploads/**` 没放行

**触发**：接线做完、准备让项目负责人目视效果时，我按惯例去**取那张背景图的字节**（而不是只看页面 HTML 里有没有 URL），
结果游客请求返回 **`302 → /login`**（`Invoke-WebRequest` 自动跟随跳转，所以第一眼看到的是"200 + text/html"，差点被误导）。

**真因**：`SecurityConfig` 的静态资源白名单只有 `"/css/**", "/js/**", "/images/**", "/webjars/**", "/favicon.ico"`
—— **独独漏了 `/uploads/**`**，于是被 `anyRequest().authenticated()` 拦下。**已登录用户正常（200 image/png），游客拿到 302。**

**影响面（比本任务大得多）**：所有**上传**的图片在**公开页面**上都取不到 ——
首页轮播封面（T-041）、社团介绍页配图（T-028）、新闻封面（T-026）、**以及本任务的首页背景图**。
换句话说：**这些成果对游客都没真正生效**。
（为什么一直没暴露：此前所有验证都只断言"页面 HTML 里有图片 URL"，**从没真的去取那串 URL 的字节**。）

**修法**：白名单加 `"/uploads/**"`（1 行）。安全说明：`uploads/` 里只有上传白名单内的图片
（jpg/jpeg/png/gif/webp），文件名是 UUID（不可猜）；获奖证书照片的 URL **不会出现在任何公开页面**。

**验证（游客视角，7 项全过）**：当前背景图 `200 image/png`（51844 字节）；首页上全部 4 张上传图逐张取字节全部 `200 image/*`；
回归确认 `/admin/students`、`/me`、`/admin/settings` 对游客**仍是 302**，公开页仍全 200。
