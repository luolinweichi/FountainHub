## 1. 任务理解

**新建 `/me`（我的主页）**，主角是 ⭐ **绿色热力图** —— 用 GitHub 那种绿格子显示「**我做了几道题**」。

### ⭐ 它和「我的考勤」是完全不同的两件事

| | 我的主页（**本任务**） | 我的考勤（T-019） |
|---|---|---|
| 回答什么 | **你做了几道题** | **你到场了吗** |

## 5. 关键设计

### 5.1 七级档位（题数）

| 档 | 当天做题数 | 颜色 |
|---|---|---|
| 未学习 | 0 | `#ebedf0` 浅灰 |
| ░ | 1 – 2 | `#c6e48b` |
| ▒ | 3 – 5 | `#7bc96f` |
| ▓ | 6 – 10 | `#239a3b` |
| █ | 11 – 20 | `#196127` |
| ██ | 21 – 30 | `#0e4429` |
| ███ | **31 以上** | `#052e16` 最深 |

用 ECharts 的 `visualMap.pieces` 写死这 7 档 —— 和 T-019 两色日历是**同一个配置位置**，只是块数不同 ✅

### 5.2 「最长连续」**按天**算（和考勤不同！）

| | 规则 | 为什么 |
|---|---|---|
| **考勤**（T-019） | **按例行活动日** —— 来了就是一周 | 例行活动是「必到」，平时不必天天来 |
| **学习**（本任务） | **按天** —— 连着几天有记录 | 参考图写的就是「最长连续学习**天数**」 |

> 两套规则不一样是**故意的**，不是笔误 ✅

### 5.3 一天多条记录怎么办
表上有 `UNIQUE (user_id, checkin_date, metric_type)`，所以理论上一天只能有一条；
代码里仍然**按日期求和**（`Map.merge`）—— 多一层防御，将来放宽约束也不会算错 ✅

### ⚠️ 那 3 条「失败」的真相

| # | 我的断言 | 实际 | 结论 |
|---|---|---|---|
| 1 | 页面里没有 `<input>` | 有 1 个（**导航的 CSRF 隐藏域**） | 我的断言没排除导航 ✅ |

### 诊断（有证据）

我把 Thymeleaf 真正吐到浏览器的 JS 抓出来了，**后端数据完全正确**：
```javascript
const valueByYear = {"2026":{"2026-09-28":1,...,"2026-10-03":35}};   ✅
const buckets = [[1,2],[3,5],[6,10],[11,20],[21,30],[31,2147483647]];      ✅
const colors  = ["#c6e48b","#7bc96f","#239a3b","#196127","#0e4429","#052e16"];  ✅
```
所以问题在**前端渲染**这一步，两个原因：

| # | 问题 | 说明 |
|---|---|---|
| 1 | **颜色太淡** | 没数据用 `#ebedf0` + 3px 白边，画在白卡片上几乎看不见 |
| 2 | **压根没画出来** | 项目负责人截图里整个日历区域**纯空白**（他有数据却没有绿格子）→ ECharts 那段 JS 没执行成功 |

**为什么我没提前发现**：开发沙箱**没有外网**，我**没法在浏览器里跑 ECharts**；
我之前的验证只检查到「引入了 `echarts.min.js` 这个标签」—— 那只证明**标签在**，
**证明不了它加载成功、画出来了**。这是验证漏洞 ✅

### 决定：**按项目负责人选的方案 A** —— 服务端渲染 CSS 格子

| | 好处 |
|---|---|
| ✅ | **不依赖 CDN、不依赖 JS** → **永远不会再白屏** |
| ✅ | 颜色完全由后端控制 → 想多明显就多明显 |
| ✅ | 符合本项目「服务端渲染」的一贯做法 |
| ✅ | **AI 能真正验证**（直接数生成的 HTML 格子和颜色） |
| ✅ | 少一个 CDN 依赖（ECharts 彻底移除） |

### 实现

- 新增 `util/CalendarGrid.java`：把一年排成 **7 行（周一~周日）× 若干列（每周一列）**，两个图**共用**
