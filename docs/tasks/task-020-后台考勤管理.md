## 1. 任务理解

给社长层一个管考勤的地方，三个能力（对应 FR-6.3 / FR-6.4 / FR-6.5）：

| # | 能力 | 说明 |
|---|---|---|
| A | **创建活动** | 日期 + 类型（例行活动必到 / 日常开放自愿）+ 标题 + 说明 |
| B | **代打卡** | 社长替学员记考勤，**必须记录是谁代打的** |
| C | **出勤率** | 每人 `到场场次 ÷ 应到场次` |

## 2. 权限（2026-10-03 项目负责人选 **A**）

| 操作 | 指导老师 | 正社长 | 副社长 | **组长** | 学员 |

| 看 / 创建 / 代打卡 | ✅ | ✅ | ✅ | **🚫 403** | 🚫 |

## 5. 关键设计

### 5.1 ⭐ 代打卡 = 一条带操作人的 ADMIN 记录
```java
record.setCheckinType(CheckinType.ADMIN);   // 不是本人签的
record.setOperatorId(me.getId());           // ⭐ 是谁代打的
record.setUserId(被代打的人);                // ⚠️ 全项目唯一能写别人考勤的入口
```
页面显示「**由 XX 代打**」✅；「何时打的」由数据库 `checkin_at` 自动记 ✅

### 5.2 「没去就空着」原则继续守住
代打卡只做 **PRESENT（到场）** 和 **LEAVE（请假）** 两种，**不提供 ABSENT** ——
没来的人在数据库里就是没有任何记录，只是出勤率的分子少一次 ✅

### 5.3 两道锁

| 层 | 做法 |
|---|---|
| 页面层 | `sec:authorize` 隐藏导航入口（只是「看不见」） |
| **服务器层** | 类上的 `@PreAuthorize` + `hasAnyRole('TEACHER','PRESIDENT','VICE_PRESIDENT')` ← **真正拦住的是这个** |

> 所以负向测试**必须直接发 POST**，不能只检查「链接藏起来没有」✅

### 5.4 避免 N+1
出勤率、代打人名都是**一次查出来做成 Map**，不在循环里查库 ✅
