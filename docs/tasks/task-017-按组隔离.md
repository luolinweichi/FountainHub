## 3. 关键设计

### 3.1 为什么**单开一个页面**，而不是让组长去用学员列表

学员列表（`/admin/students`）天生要显示**学号、角色、状态、审核/禁用/改角色按钮**。
要让组长"只能用其中一点点"，就得在那里到处加判断 —— **加漏一处就是越权**。

**单开一个小页面，从设计上就不可能泄漏**别的信息 ✅
（页面里根本没写那些字段，不是"藏起来"，是"不存在"）

### 3.2 权限三分法（⭐ 项目负责人特别纠正过这一点）

| 身份 | 访问 `/me/group` | 为什么 |
|---|---|---|
| **组长**（含"社长兼组长"） | **200** → 看自己的组 | 这就是这个页面的用途 |
| **社长层但不带组** | **302 → `/admin/groups`** | ⭐ **不是 403**！他权限最高，只是这个页面不如分组管理页全 → **给他指一条更全的路** |
| **普通学员** | **403** | 他确实没有任何组可看 |

> 🙏 这一点是项目负责人当场纠正的：我最初的方案把"不带组的社长"和"普通学员"都算成 403，
> **那与「社长所有页面都能看」的权限设计自相矛盾**。

### 3.3 403 要是**真正的 403**

不是 `return "redirect:/403"`（那样 HTTP 状态码是 302），而是抛 `AccessDeniedException` ——
交给 Spring Security 统一处理，**状态码是真正的 403** ✅

### 3.4 导航栏怎么知道"我是不是组长"

`sec:authorize="hasRole('LEADER')"` —— 靠的正是 **T-016 的派生身份**（被指定为组长 → 登录时自动多一个 ROLE_LEADER）✅

### ⚠️ 那 1 条"失败"的真相

```

```

**原因**：我在页面底部写了一段**说明文字**给组长看 ——
「🔒 你看不到：学号、**角色**、在社状态、以及任何人的手机号」。
