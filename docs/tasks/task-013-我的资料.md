## 1. 目标

已登录的用户在 `/me/profile` 看自己的资料，**只能改联系方式**：

| 区域 | 字段 | 能改吗 |
|---|---|---|
| **只读** | 真实姓名、学号、用户名、**手机号**、角色、状态、入社日期 | ❌ |
| **可改** | **QQ / 微信 / 邮箱** | ✅ |

### 为什么手机号也不能自己改（2026-10-02 项目负责人决定）

手机号是**登录凭据**（三种登录方式之一）＋唯一标识，比 QQ/微信敏感得多。
让它跟 QQ 一样"谁都能自己改"，账号安全就没保障了 —— **与姓名、学号同级别，只能管理员改**。

**依据**：[spec.md](../spec.md) §4.1 验收、[01-需求规格说明书](../01-需求规格说明书.md) **FR-2.7**（本任务已按此收紧）。

## 4. 两条安全铁律（本任务的核心）

### 🔒 铁律 1：从**会话**取当前用户

`java
User me = userRepository.findByUsername(authentication.getName()).orElseThrow(...);
`

URL 里**根本没有 id 参数** → 天然只能改自己 → "改不了别人的资料"这条验收就是这么实现的。

### 🔒 铁律 2：只显式接收允许的字段（防**批量赋值**）

`java
// ❌ 绝不能写成整体绑定：
//    public String save(@ModelAttribute StudentProfile p)
//    攻击者能在请求里偷塞 role=TEACHER，Spring 会老实帮他绑上去 —— 直接提权

// ✅ 只收这 3 个：
@RequestParam String qq, @RequestParam String wechat, @RequestParam String email
`

## 5. 风险与不确定点
