## 1. 任务理解

spec 的原文要求（两处）：

> 🚫 学员手机号**不得出现在任何公开页面** —— 首页、新闻列表/详情、获奖展示墙、排行榜等**游客可见的地方一律不许带**

> - [ ] **公开页面**扫描确认没有任何学员手机号（**管理员后台详情页可见**，见第 3.3 节修订）

所以本任务要**证明**三件事：

| # | 要证明 | 判据 |
|---|---|---|
| 1 | **游客能打开的每一个页面**里都没有手机号 | 用游客身份抓全部公开 URL → 正则扫 |
| 2 | **导出文件**里没有手机号列 | 下载两个导出接口的 CSV → 检查表头与内容 |
| 3 | **代码里没有意外泄漏**（模板注释、JS 注释等） | 全库扫模板源码 |

## 2. 🔑 一个必须说清楚的边界

**「学员详情页」（`/admin/students/{id}`）是允许显示手机号的** ✅
依据：spec §3.3 的修订 —— 那是**管理员专用**页面，`@PreAuthorize` 只放社长层进来。

所以本任务**不是**「全站都不许有手机号」，而是：

```
游客能看到的地方  → 绝对不许有 ❌
管理员后台详情页  → 允许有 ✅（这是需求，不是 bug）
导出文件          → 不许有 ❌（导出会被到处转发）
```

## 3. 非目标

- ❌ **不改任何代码**（除非查出泄漏 —— 那也**先报告，不擅自改**）
- ❌ 不改数据库、不改手机号本身的存储方式
- ❌ 不做「手机号脱敏/加密」这类功能改造（那是另一个话题）
- ❌ 不做性能/样式相关的事
