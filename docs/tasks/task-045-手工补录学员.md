## 1. 目标（这个任务要达成什么）

让管理员能在后台**直接补录一名学员**，一次完成「**建账号 + 建档案**」。两个真实用途：

1. **换机 / 重建库后把正式名单补回来** —— 现在只能让每个学员自己去 `/register`；
2. **招新时录入线下收上来的名单** —— 一期不做批量导入，先一个个录。

硬性要求：

1. 表单字段与「学员详情编辑页」**同一口径**：姓名 / 学号 / 用户名 / 手机号 / 组别 / 年级 / 专业班级 / 擅长语言 / 阶段 / 状态。
2. 落库 = `users` **一行**（BCrypt 哈希）+ `student_profiles` **一行**（一对一，主键 = 同一个 id）。
3. 唯一性（用户名 / 学号 / 手机号）重复时给**人话提示**，**不是 500** —— 做法对齐 `RegisterController`，避免 `REFACTOR_PLAN` **R-011「校验文案不统一」**再扩散。
4. 建完能**立刻**用**学号 / 用户名 / 手机号**任一 + 密码登录（对齐 §8 验收第 1 条）。
5. 失败时把已填内容**回填**（不让管理员重打一遍）。

### 关键实现决定

1. **不在控制器里写 11 个参数的 refill**：改用 `Map<String,String>` 装"用户填过的内容"再统一塞进 Model ——
   `RegisterController.refill()` 原来就是 13 个参数被改过（**R-010**），这里**从一开始就不重复那个坑**。
2. **密码不回显**（`filled` 里故意不含 password / confirmPassword）。
3. **先 `save(users)` 再建档案**：`users` 是 IDENTITY 主键，`save` 之后 id 已回填，`student_profiles` 主键直接用它（一对一）。
4. **`@Transactional`**：两张表要么一起成功、要么一起回滚，不留"有账号没档案"的半成品。
5. **路由优先级**：本类有 `@GetMapping("/{id}")`，它**也能匹配** `/new`；靠 Spring「**字面量优先于变量**」命中 `/new` ——
   **已实测 `GET /admin/students/new` = 200**（若被 `/{id}` 抢走，`Long id` 转 "new" 会直接 400）。
