## 1. 目标

后台学员列表，只对「指导老师 / 正社长 / 副社长」开放：

| 功能 | 实现 |
|---|---|
| 列表 | 姓名 / 学号 / 角色 / 状态 四列 |
| 关键词搜索 | 一个输入框，**同时匹配姓名或学号** |
| 状态筛选 | 下拉框（在读 / 退社 / 毕业 / 已禁用） |
| 分页 | 每页 10 条，带"上一页 / 页码 / 下一页" |
| 🔒 手机号 | **不查、不传、不显示**（硬性红线） |

### 两个关键设计决定

| # | 决定 | 为什么 |
|---|---|---|
| 1 | 用 `Specification` 拼条件，**不写 8 个组合方法** | 3 个筛选项有 2³ = 8 种组合，逐个写方法会**组合爆炸**；Specification 让每个条件变成可拼装的一小段 |
| 2 | **「按组筛选」和「组」列不做**（挪到 T-016） | 需要 StudyGroup 实体（T-015 的事）。**项目负责人 2026-10-02 选方案 A**：保持"纵切（按模块）"的拆分 |

### 遇到的问题（如实记录）

| # | 问题 | 根因 | 处置 |
|---|---|---|---|
| 1 | `/admin/students` 首次访问 **500**：`SpelParseException: Expression [/admin/students]` | **同一个错误犯了第二次**：`th:action` / `th:href` 需要的是**链接表达式** `@{...}`，我又写成了 `${...}`（变量表达式） | 修 4 处，并在**全项目所有模板**里加了一道自动扫描，确认再无同类问题 |
| 2 | 我的验证脚本两次误判 | ① 用"用户名"去匹配，但表格显示的是**真实姓名**；② 用 `class="tag"` 精确匹配，但 `th:classappend` 会把类名合并成 `class="tag active"` | 改成正确的判定后全绿。**教训：验证脚本的期望值也要先核对清楚，否则会自己骗自己** |

**记住（这次是第二次栽了）**：
- `@{/login}` = **链接**表达式 → 用在 `th:action` / `th:href` / `th:src`
- `${error}` = **变量**表达式 → 用在 `th:if` / `th:text`
- **写完模板一定要扫一遍**：`th:(action|href|src)="`${` 就是错的
