> **建立日期**：2026-10-04
> **地位**：本文件是 FountainHub **对外身份的唯一权威** —— 决定 README 怎么写、哪些词必须改、哪些词必须留。
> **配套**：[README](../README.md)（对外门面，已按本文件落地）｜[spec.md](spec.md)（内部契约）｜[00-快速开始](00-快速开始.md)（怎么改造）

## 0. 为什么要有这份文档

项目里原本只有**一种身份**，而且它是**内部的**：

| | 站在谁的角度说话 | 原来的落点 | 结果 |
|---|---|---|---|
| **A 内部契约** | "我是这个社团的技术负责人" | [spec.md](spec.md) §1：「让**本社团**（约 100 名学员）能真正每天用起来」 | 只对**我们自己**有意义 |
| **B 对外定位** | "我是这个开源项目的作者" | ❌ **原本空缺** | 别人打开仓库**不知道该拿它干什么** |

> 📌 **教训**：2026-10-04 做开源准备时，一开始只想着"把词换掉"，换到一半才发现——
> **"哪些词必须改"根本是由 B 决定的**。B 没定义就动手，等于**照着旧衣服改小，却没决定这件衣服要卖给谁穿**。
> 所以定 B **优先于**任何改名动作。

## 1. 一句话定位

> **FountainHub —— 一个开箱可用的校园社团管理系统，也是一份完整的、从需求到上线的开发实录。**

复合定位（记作 **P1 + P3**）：

| 代号 | 定位 | 作用 |
|---|---|---|
| **P1** | **通用校园社团管理系统** | 让项目**有用** —— 别的社团克隆下来改几行配置就能用 |
| **P3** | **SDD 全栈开发实录** | 让项目**有故事** —— **11,000+ 行文档 + 近 3,000 行开发日志 + 39 份任务书**，这是大多数学生项目没有的 |

> 两者**共用同一套代码**，不冲突：给社团用是工具，给学习者看是范例。
> **增量成本几乎为零**（P3 只花写作，不花返工）。

## 2. 对外门面文案 —— **已落地，不在本文件维护第二份**

README 的开头两段曾在这里起草。**现已正式写入 [`README.md`](../README.md)**。

> ⚠️ **为什么现在这里不抄一份**：同一段文案写在两处，**一定会漂移**（一处改了另一处忘）。
> 从这一刻起：**README 是门面文案的唯一所在**，本文件只负责"为什么要这么写"。

**门面要回答的三件事**（写作约束，不是文案）：

1. **这是什么、给谁用** —— 一句话说清，别让人猜；
2. **它不是什么** —— 明确边界，防误解（见 §4）；
3. **我拿它能干什么** —— 跑起来 / 改成自己的 / 看它怎么做出来的。

## 4. 它是什么 / 不是什么

| ✅ 是 | ❌ 不是 |
|---|---|
| 校园社团的内部管理后台（改配置即可用） | 学校的管理信息系统 —— **没有**成绩、学分、排课、学籍 |
| 服务端渲染（Thymeleaf）的全栈示例 | 通用 SaaS / 多租户平台 |
| 一份可读的开发实录（文档 + 日志 + 任务书） | "生产级 / 高并发"系统 |
| 单人 + AI 结对完成的作品 | 商业产品 / 对外服务 |

> ⚠️ **这张表必须进 README** —— 它是防误解的第一道闸门。
> 注意表述方式：**用"我们不做什么"来划边界**（不做成绩/学分/排课/学籍），
> 而不是用"我们不是某某系统"—— 后者会把不该出现的词带进文档里。

## 5. 从定位推出的硬决定（后续所有工作以此为准）

| # | 决定 | 依据 |
|---|---|---|
| **1** | **业务词全部保留**：社团 / 学员 / 学号 / 考勤 / 分组 / 获奖 **一个都不改** | P1 是"社团管理系统"，这些词**本来就是对的**；泛化它们（学员 874 处、学号 204 处）还要动 DB 列名与路由，成本高且易出 bug |
| **2** | **系统名统一叫「社团管理系统」** | 短、自然、准确；也避开了"学校 / 教学管理"这类容易引起误解、且与本项目**实际功能不符**的说法（本项目没有成绩与排课） |
| **3** | **README 从"进度表"重写成"门面"** | ✅ **2026-10-04 已完成** |
| **4** | **只清"身份层"**：真实社团名、能反查到学校的信息（校内地标 / 具体年级）、真实海报与社徽 | 任何定位都跑不掉 |

## 6. 对外的"不做什么"（写进 README 的负范围）

- ❌ 不做在线判题（OJ）；**不做成绩 / 学分 / 排课 / 学籍**
- ❌ 不做移动端适配（本期只针对 **1440 / 1920 桌面视口**）
- ❌ 不引入前端框架（React / Vue 一律不引）
- ❌ 不承诺生产级可用性（是**作品**，不是**产品**）
- 🚧 在线题库与教学视频属**二期**：一期只写了 [接口契约](10-题库API契约.md)，没有界面
