## 5. 配置 MySQL

### 5.1 创建数据库

用 DBeaver 或命令行执行我们写好的脚本。
⚠️ **`mysql` 不在 PATH，必须写全路径**；并且**四个脚本要按顺序全跑**（共 20 张表）：

```bash
# 1. 建库建表（19 张，v1.1 起已含 password_reset_requests）
"C:\Program Files\MySQL\MySQL Server 26.7\bin\mysql.exe" --default-character-set=utf8mb4 -u root -p < sql\01-schema.sql

# 2. 写入初始数据（小组 / 示例新闻 / 示例章节）
"C:\Program Files\MySQL\MySQL Server 26.7\bin\mysql.exe" --default-character-set=utf8mb4 -u root -p < sql\02-seed.sql

# 3. 增量补第 19 张表（忘记密码申请，T-012B）—— 幂等
"C:\Program Files\MySQL\MySQL Server 26.7\bin\mysql.exe" --default-character-set=utf8mb4 -u root -p fountainhub < sql\03-add-password-reset-requests.sql

# 4. 增量补第 20 张表（站点设置 site_settings，T-042）—— 幂等
"C:\Program Files\MySQL\MySQL Server 26.7\bin\mysql.exe" --default-character-set=utf8mb4 -u root -p fountainhub < sql\04-add-site-settings.sql
```

> ⚠️ **为什么第 3、4 步不能省**：`01-schema.sql` 只到 **19 张**（它不含 `site_settings`）。
> 而 `src/main/resources/application.yml` 里 `spring.jpa.hibernate.ddl-auto=validate` ——
> 表对不上时应用**启动直接失败**（报 `missing table [site_settings]`）。
> 📌 本机库这两个增量脚本**早已执行过**（2026-10-04 实测库中 20 张表），**不要重复执行**。

### 5.2 验证

```sql
USE fountainhub;
SHOW TABLES;          -- 应该看到 20 张表（只跑 01+02 的话是 19 张，缺 site_settings）
SELECT * FROM study_groups;   -- 应该看到 Python 组、C 语言组
```

### 5.3 千万不要做的事

- ❌ 不要用 root 账号给应用连接（以后可以建一个专用账号）

## 7. 新手最容易踩的 7 个坑

| # | 坑 | 现象 | 解决 |
|---|---|---|---|
| 1 | JDK 版本不对 | 启动报 `UnsupportedClassVersionError` | 换 JDK 17 或 21 |
| 2 | 端口被占用 | 启动报 `Port 8080 was already in use` | 关掉占用的程序，或改 `server.port` |
| 3 | MySQL 时区/编码 | 中文变问号 `???` | 连接串加 `?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai` |
| 4 | Maven 下载慢 | 一直卡在 Downloading | 配置国内镜像（阿里云 Maven 镜像） |
| 5 | 编码不是 UTF-8 | 中文乱码 | 见第 6 节 |
| 6 | 忘了 MySQL 密码 | 连不上 | 用 `--init-file` 方式重置（本项目已备好 `tools/reset-mysql-root.ps1`） |
| 7 | **中文输入法污染代码** ⭐ | 代码里混进「啊？」「是这样的。」，或中文引号 `""`、中文括号 `（）` | 编译报莫名错误 / YAML 报 `ScannerException` | 编辑代码前按 **Shift** 切到英文；确认右下角输入法是「英」。本项目已实际踩过 2 次 |

## 10. 常见问题

### Q：我需要搭建 Linux 虚拟机吗？

> ⚠️ **本问题的结论已于 2026-10-02 由项目负责人改写**：原结论是「**不需要**」，**新结论是「要」**。
> 原结论完整保留在本节末尾的「历史记录」里，不删除。

**A：要。搭一台 Ubuntu 22.04 LTS（Server 版）虚拟机**，并把它作为**最终部署环境的预演**（虚拟机与线上系统用**同一个操作系统**）。
任务编号 **T-038**，见 [plan.md](plan.md)。

#### 为什么这么定

| # | 理由 |
|---|---|
| 1 | CentOS 已转向 **CentOS Stream**（定位为 RHEL 上游），稳定性预期下降，不适合学生项目 → **放弃 CentOS** |
| 2 | Ubuntu **LTS 社区最大、教程最多、软件源新**，对新手与开发者最友好 |
| 3 | 项目后续可能用到 **Docker / K8s 等云原生技术**，Ubuntu 支持最好 |

> 📌 **这不是推翻一条已记录的 CentOS 决策** —— 本仓库此前**从未**记录过操作系统为 CentOS
> （全量搜索 `CentOS` / `RHEL` / `Rocky` / `AlmaLinux` = **0 处命中**）。本次是**首次定案**。
> 与 [04-部署方案](04-部署方案.md) §7 原先写的「Ubuntu 22.04 / 24.04 LTS」**方向一致**，只把版本收窄为 **22.04**。

#### 选哪个版本

| 选项 | 决定 | 原因 |
|---|---|---|
| **Server 版**（无桌面） | ✅ **选它** | 没有图形界面 → 基础系统只要 ~0.4 GB，全栈峰值也才 ~2.5 GB（见下方「资源规格」） |
| Desktop 版（有桌面） | ❌ 不选 | 光桌面就要 2 GB 起，会和 IDEA 抢内存 |
| 24.04 LTS | ❌ 不选 | 22.04 更成熟、教程更多，且与 [04](04-部署方案.md) 的云服务器镜像保持一致 |

#### ⚠️ 原「三个别装虚拟机的理由」**并没有过时** —— 转为**配置约束**

原来那 3 条理由今天依然成立，所以虚拟机**必须按约束配**，不能敞开了跑：

| # | 原理由 | 2026-10-02 的处置 |
|---|---|---|
| 1 | **吃资源**（虚拟机要分 2～4G，和 IDEA + MySQL 抢内存） | ⚠️ **仍然成立，且是最关键的一条** —— 但**已用「换宿主」这一步解开**：台式机物理内存实测仅 **7.4 GB**（见 07 §3），**给不出**全栈预演所需的 ~2.5 GB，因此**虚拟机改放笔记本**（20 GB 内存）。详见下方「资源规格」 |
| 2 | **没必要**（开发期工作在 Windows 上做的一模一样） | 🟡 **部分成立** —— 写业务代码仍在本机 Windows 上做；虚拟机的用途是**练 Linux + 预演部署**，不是替代本机开发 |
| 3 | **有更好的替代**（直接用真实云服务器练） | 🟡 **部分成立** —— 云服务器仍是最终上线首选；虚拟机的好处是**免费、可快照回滚、装坏了随便重来** |

#### 资源规格（2026-10-02 定案 ｜ 2026-10-04 按实际复核）

| 项 | 值 |
|---|---|
| **宿主** | 💻 **笔记本**（i7-7500U，**20 GB 内存**）—— **不是台式机** |
| 用途 | **全栈预演**：Docker + MySQL + Spring Boot jar + Nginx |
| vCPU | **2** |
| 内存 | **8 GB** ⚠️（**以实际给到的为准**：早期曾计划 **6 GB**「宽裕可给 8 GB」，**实际给的是 8 GB** —— 与 [README](../README.md) 进度表、07-本机环境检测报告 §1 统一） |
| 磁盘 | **60 GB 精简置备**（thin） |
| swap | **4 GB** |

**为什么宿主是笔记本而不是台式机**：台式机物理内存实测只有 **7.4 GB**，而全栈预演峰值约 **2.5 GB** ——
给完虚拟机就没法再开 IDEA，**开发和预演会互相干扰**。笔记本 20 GB 内存则毫无压力，
而且**两台机器互不干扰，更接近真实的上线形态**（上线时应用本来就跑在另一台 Linux 上）。

> ❌ **台式机上的「2核8GB」已被否决**：8 GB **大于**台式机**全部**物理内存 7.4 GB，
> 属于**物理上给不出来** —— VMware 会拒绝开机，或把宿主拖进疯狂换页（硬盘灯长亮、两边一起卡死）。
> 另：**CPU 不是瓶颈**（台式机 6 核 12 线程），**内存才是**。

**三条纪律**：

1. **不要在虚拟机里编译**：`mvn package` 在台式机做（6 核，快），把 jar 拷到笔记本虚拟机**只运行** —— 这恰好符合「服务器只运行、不编译」的真实形态；
2. **VMware 不要勾 "Reserve all guest memory"**（预留全部内存），否则宿主内存会被立刻锁死；
3. 虚拟机文件放笔记本**空间充足的盘**，并使用**精简置备**（thin）。

**开机前 3 项核查**（笔记本的情况资料里没有，需你确认）：

| # | 核查项 | 为什么 |
|---|---|---|
| 1 | 笔记本**剩余磁盘空间** ≥ 60 GB（建议 80 GB 以上） | 虚拟机磁盘 + 快照 |
| 2 | 笔记本**能否长期开机** | 当宿主意味着它要经常开着 |
| 3 | **两机之间怎么传文件** | ⚠️ [plan.md](plan.md) §4 待商定项 4：**GitHub 首次推送至今未完成**，「用 Git 同步」这条路目前还不通；可先用局域网共享 / scp / U 盘 |

#### 什么时候做

**与业务开发并行**（M3 期间即可动手）。它是**环境准备**，**不修改任何业务代码**。

#### 历史记录（2026-10-02 之前的原结论，留档，以下内容不再代表当前决定）

> **A：不需要。开发阶段完全用不到 Linux。**

| 阶段 | 用什么系统 | 原因 |
|---|---|---|
| 写代码 / 本地运行 | **Windows** | Spring Boot 是跨平台的，Windows 和 Linux 跑起来完全一样 |
| 部署上线 | **Linux**（云服务器） | 云服务器默认就是 Linux，不需要你自己造一个 |

#### 三个"现在别装虚拟机"的理由

1. **吃资源**：虚拟机至少要分 2～4G 内存，而 IDEA + MySQL 本来就很吃内存。
   同时开会让电脑**非常卡**，严重影响开发体验。
2. **没必要**：开发期的全部工作（写代码、跑测试、连本机 MySQL）在 Windows 上做的事**一模一样**。
3. **有更好的替代**：真到部署的时候，直接用**真实云服务器**练，
   比虚拟机真实得多，而且学生机只要 ¥40/月，或者按量付费几毛钱一小时。

#### 什么时候才需要接触 Linux？

**第 3～4 周，部署阶段。** 到那时候：

- 买一台云服务器（或者让指导老师提供），它**本身就是 Linux**；
- 你实际要学的命令只有五六个：`ls`、`cd`、`systemctl`、`tail`、`chmod`、`nano`；
- 到那一步我会**手把手带你**，不需要提前准备。

#### 如果实在想提前熟悉一下

用 **WSL2**（Windows 自带功能，比虚拟机轻量得多）：

```powershell
wsl --install
```

一条命令装好 Ubuntu，**共享磁盘、启动秒开、不额外分区**。
但这不是必须的，**不着急**。

#### 一句话总结

> **现在专心在 Windows 上把功能写出来。Linux 是最后一步的事，而且到时候你会觉得它比想象中简单得多。**
